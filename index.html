地址不是猜的，是查回来的

没有内置一张需要你维护的地址表。每次点「检查」，都是从包名现查现取：应用发了新版本，下一次点开拿到的就是新的。

取址链路 request → parse

  1. 读出已安装应用清单，取包名与当前版本号
  2. 按包名请求详情数据，定位这个应用那一段字段
  3. 取出 version_name、apk_size、download_url
  4. 直链统一转 https，交给下载器
android.myapp.com/myapp/detail.htm?apkName=<pkg>

下载链路 206 → parts

  1. 先发 Range: bytes=0-0 探测，读回文件总长度
  2. 支持分段就切八段，各段写入同一文件的对应偏移
  3. 不支持 Range 就退回单连接，不会卡在半路
  4. 八段都结束才校验总字节数，对不上就报错并清理
301/302/307/308 手动跟随 · 含 http 到 https

做不到的事，写在明面上

这些不是 bug，是安卓的权限模型和第三方数据源的现状决定的。装之前先看清楚，省得期待落空。

01替你点安装

系统禁止应用静默安装别人的安装包。下载完成后必须你点一次安装，再在系统弹窗里确认，这一步谁也绕不过。

02比厂商发版更快

自动取的是商店收录数据，与厂商发版之间常有几小时到几天时差。微信保留了官方更新页通道，要最快那一版可以走它。

03穿过登录与防盗链

需要登录、或对来源做了限制的下载地址可能取不到。这类情况会明确提示，并转到内置浏览器让你自己点。

04保证每个应用都有源

没有公开收录的应用查不到版本与直链，这不是失败，是数据源里没有。此时可以手动填一条，或直接用浏览器。

常见问题

装之前值得知道的几件事。

怎么装？需要给哪些权限？

把 APK 传到手机点开安装，按提示允许「安装未知应用」。首次启动请求通知权限，用来显示下载进度，拒绝也能下载。读取应用列表只在本机使用，不上传任何应用信息。

为什么查到的版本有时比官方旧？

取的是商店收录数据，收录与厂商发版之间有时间差。需要最快版本时，可以在应用内走官方更新页那条通道，或者用内置浏览器打开官方页面自己点。

下载到一半失败是怎么回事？

常见两种：对方不支持 Range 却返回 200，下载器会退回单连接重来；或者地址是临时的，过期后 403/404。失败会在通知栏说明原因，临时文件同时清掉，重试即可。

它和这些被更新的应用是什么关系？

没有关系。它不是任何应用的官方客户端，也不修改、不重打包安装包：版本与安装包都来自各应用自己的分发地址，下到的文件与在商店拿到的是同一个。

源码能看吗？

可以。源码包内含 src/、res/、AndroidManifest.xml 与一个 build.sh（javac → d8 → aapt2 → zipalign → apksigner，不需要 Gradle），不含签名私钥与构建产物。
